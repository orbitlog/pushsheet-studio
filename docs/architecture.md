# 实现约定

## 数据流

源文件 → `SourceTable`（保留源行用于映射核对）→ `PushProject[]` → 共用编辑 / 预览 → 校验 → 定向 OOXML 填充 → 独立 XLSX / ZIP。

粘贴和手动输入共用 `PushProject` 模型。文件导入追加项目，不按同名 ID 合并；同名 ID 会阻止导出，用户可以在编辑器修正。源文件「重新解析」会提示替换现有编辑。

## 写入边界

`inspectTemplate` 读取工作簿关系以定位真正的工作表路径，不依赖 `sheet1.xml`。工作表名、表头行、类型列和标签均可配置。

`fillXlsx` 在导出前再次校验，打开原 ZIP，对已选语言的全部配对行写入 inline rich text。正则只定位 XML `<c>` 节点，不对工作表进行整体 DOM 序列化。DOM 仅用于读取与最终语法检查。缺失的目标单元格按列顺序插入已有行。除目标工作表 XML 之外的 ZIP 部件原样写回。

`Intl.Segmenter` 划分字素簇，普通文字与 Emoji 分别组合为运行段。优先继承目标单元格的运行段字体，其次使用工作簿内的 Emoji 样例字体。文本始终写作字符串，不解释 HTML 或公式。XML 特殊字符、字面 OOXML `_xNNNN_` 文本和回车均单独编码处理。

原始模板固定行高 / 列宽不会自动调整。长文案可在网页文本域中完整编辑，但 Excel 视觉效果仍由模板决定。

## 本地与安全边界

没有后端、遥测、Cookie 或 LocalStorage。默认模板从本站静态资源读取；浏览器中的上传对象不会通过 fetch、XHR 或表单发送。所有提示通过 Vue 文本插值呈现。

先检查 ZIP 中央目录中声明的总解压大小，再交给 JSZip 解压。对文件大小、单批大小、工作表数、实际单元格数和坐标范围设限。拒绝带密码 / 宏、分卷与过大文件。当前不支持恶意文件的全面内容净化，用户自定义模板中的非目标原始部件按保真要求保留。

## 测试原则

公开仓库中只保留合成文案与已经清理的默认模板。`PUSHSHEET_FIXTURES_DIR` 启用私有真实文件回归，文件和输出不进入版本控制。模板保真测试比较解压后部件字节与目标以外的工作表 XML，不能用生成文件总体字节相等代替。

原生 Excel / WPS 的打开验证与浏览器测试是补充检查。回归测试能证明字符与 XML 样式结构保留，不能证明所有系统都有相同的 Emoji 字体或像素显示。
